# OfflineTranscription

`offline_transcription` is a synchronous Qt Core C++ shared library that loads the application's bundled audio.cpp C ABI at runtime. It accepts 16 kHz mono signed little-endian PCM16 and returns newly confirmed sentences and a replaceable draft for independent MIC (1) and SPK (2) streams. All calls for an engine instance must be serialized on a worker thread. Inference runs on that worker.

The embedded, unmodified header is from audio.cpp commit `047fb4243914583e23c41d37f28185f0ebfe1bba`, ABI 0.3.0. The application ships the matching runtime; the user only selects a Qwen3-ASR GGUF model file. Nothing is downloaded during configure, build or transcription. The runtime must expose streaming support for `qwen3_asr`. The Windows runtime must support Vulkan, and macOS must support Metal. If creating a GPU session fails, loading fails; there is no CPU fallback. Linux can build, but has not been validated for this application.

The checked-in `lib/macos/arm64/libaudiocpp.dylib` is copied from the reference OfflineTranscriptionManager package, with its provenance, build options and SHA-256 recorded in `lib/macos/arm64/artifact.json`. It requires macOS 14.4 or newer and contains embedded Metal shader source, so no separate metallib or source checkout is needed. Development builds copy it into `Chunfe.app/Contents/Frameworks`; installation copies it to the same location and includes licenses under `Contents/Resources/licenses/audio.cpp`. Deleting the development copy is repaired on the next build. Test executables receive a copy alongside the executable.

Release maintainers can provide another platform's package using the CMake-only `CHUNFE_AUDIOCPP_RUNTIME_DIR` directory. Windows packages place the Vulkan `audiocpp.dll` and redistributable dependency DLLs beside `Chunfe.exe`, with notices under `licenses/audio.cpp` in the same directory. The reference name `audiocpp-vulkan.dll` is also accepted and deployed as `audiocpp.dll`; a separate CPU `audiocpp.dll` is excluded in that case. The directory must contain all required redistributable libraries (such as the matching MSVC/OpenMP runtimes); the Vulkan loader comes from the graphics driver. Linux optionally installs a supplied `libaudiocpp.so` and adjacent shared libraries to `${CMAKE_INSTALL_LIBDIR}/chunfe`. A runtime path is never stored in user preferences or displayed in the configuration page.

This checkout does not contain Windows or Linux runtime binaries: offline transcription is unavailable on those platforms until a verified GPU runtime package is supplied. Their existing application installers can still be built, with explicit configure/install warnings. The CMake-only `CHUNFE_REQUIRE_AUDIOCPP_RUNTIME` option defaults to `ON` on macOS, where a runtime is shipped, and `OFF` on Windows/Linux. When enabled, a missing runtime rejects installation; release maintainers enabling offline transcription on another platform should also enable this check. GPU initialization is always required when loading an available runtime, regardless of the packaging option. Windows/Linux inference has not been validated here.

`load` creates one model and one GPU session. Each source keeps its own PCM and text state. `push` decodes every second with up to four seconds of overlapping audio and a maximum of 64 generated tokens per call. Successive drafts are aligned by words and characters. If the overlap cannot be aligned, the engine preserves the existing draft and decodes the new audio on its own. `finish` drains the remaining PCM before clearing the source. `reset` clears one source while retaining the loaded model. The worker waits for inference to return before unloading the session or library.

The `tests` directory builds a fake C ABI library to check loading, GPU selection, dual-source isolation, incremental output, finish behavior and error paths without a model or GPU. Fake-runtime tests do not establish real recognition quality or latency.

The optional application lifecycle tests use the deployed runtime automatically. Set `CHUNFE_REAL_ASR_MODEL` to the absolute GGUF filename and `CHUNFE_REAL_ASR_WAV` to a 16 kHz mono PCM16 WAV. Run `offline_transcription_lifecycle_tests realGpuDualChannelSpeechThroughCaptureSignals` for dual input or select `realGpuContinuousMicPreservesTextThroughFinal` for a 22.4-second MIC replay. These tests inject PCM through the capture signals at real-time speed.

The bundled Silero VAD model uses independent CPU streaming sessions for MIC and SPK. Capture PCM reaches VAD continuously in 512-sample frames. A speech start includes up to 300 ms of pre-roll. VAD confirms an endpoint after 800 ms of non-speech and returns the end sample. A 640 ms hold lets ASR retain 200 ms beyond the detected end and omit the rest of the confirmation audio when it is still buffered. Finalization follows the accepted tail and precedes PCM for the next utterance. Audio stays contiguous during shorter pauses. During sustained speech, stable sentence-ending punctuation can finalize a capsule. Capture stop drains the remainder of the active utterance, including a partial VAD frame. Closing, restarting, source failure and stop timeout invalidate queued ASR work before it calls the engine. The worker waits for an in-flight native call to return before resetting. The ABI provides no reliable token-limit finish reason.

The opt-in `offline_transcription_soak_tests` target runs ten 60-second dual-channel phases (silence, low-amplitude noise, speech, audible noise, mixed speech/noise, repeated transitions and recovery). Set `CHUNFE_RUN_ASR_SOAK=1`, `CHUNFE_REAL_ASR_MODEL`, `CHUNFE_REAL_ASR_WAV`, and `CHUNFE_SOAK_JSONL` when invoking it directly. Its QtTest timeout automatically covers the configured phases and startup/recovery allowance, unless `QTEST_FUNCTION_TIMEOUT` is explicitly set. `CHUNFE_SOAK_RENDER_PROBE=1` opens a small animated Qt Quick window and records frame submission intervals; on macOS this probe uses Metal. Do not set `QT_QUICK_BACKEND=software` or `QT_QPA_PLATFORM=offscreen` for the rendering measurement. `scripts/diagnostics/offline_transcription_monitor.py --log system.jsonl -- <test command>` adds system swap/compression and independent scheduling measurements, and stops only its own test child if memory pressure or stalls become severe. The default CTest invocation skips the GPU soak. This workload injects PCM through the capture signals and measures response with the Qt and system probes.

Set `CHUNFE_REAL_ASR_SPK_WAV` to use different speech on the two channels. This mode repeats simultaneous utterances in six-second cycles for 600 seconds by default, with the last pair drained by `pcmEnded`. Set `CHUNFE_SOAK_MIC_EXPECTED` and `CHUNFE_SOAK_SPK_EXPECTED` to the reference transcripts for the runtime and model under test. The test combines finalized capsules per source and cycle, compares the text against the references, and records first-text and finalization latency. The [shared model verification record](../../docs/testing/offline-transcription-shared-model-2026-11-13.md) documents the earlier independent-window build and its fixtures.
